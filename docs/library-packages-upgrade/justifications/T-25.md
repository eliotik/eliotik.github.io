## 1. Goal recap

Bump TypeScript, Prettier, prettier-plugin-astro, prettier-plugin-tailwindcss, Husky, and lint-staged to their current latest stable versions; run a formatter pass to apply any new defaults; and verify that TypeScript 6.0.3 does not introduce regressions.

## 2. What changed

- `package.json` + `pnpm-lock.yaml`: version bumps for the six target packages (see §3 for exact versions).
- `.prettierignore`: added `src/layouts/Layout.astro` exclusion with comment explaining the `prettier-plugin-astro@0.14.1` parser regression on function declarations inside `<script type="text/partytown">` blocks.
- 77 source files: auto-format reflow by Prettier (whitespace/indentation normalization; no semantic changes).
- `eslint.config.js`: added JSDoc cast to resolve TS 6 iterator error on `tsPlugin.configs['flat/recommended']` spread.
- `src/pages/og.png.ts`: wrapped `generateOgImageForSite()` return in `new Uint8Array(...)` to resolve TS 6's stricter `Buffer<ArrayBufferLike>` → `BodyInit` assignability.
- `src/pages/posts/[slug]/index.png.ts`: same `new Uint8Array(...)` wrapper for `generateOgImageForPost()`.
- `src/pages/posts/[slug]/index.astro`: changed `relatedPosts.map(getEntry)` + direct assignment to a filtered assignment using a type predicate, resolving TS 6's error that `getEntry` can return `undefined`.

## 3. Why this approach

This task implements §4 Task T-25 of the upgrade plan: bump the TypeScript toolchain to current stable. The `pnpm add -D ... @latest` command is the canonical approach; all exact resolved versions are recorded here.

**Version bumps (before → after):**
- `typescript`: 5.3.3 → **6.0.3**
- `prettier`: 3.8.3 → **3.8.3** (already at latest; no change)
- `prettier-plugin-astro`: 0.13.0 → **0.14.1**
- `prettier-plugin-tailwindcss`: 0.8.0 → **0.8.0** (already at latest; no change)
- `husky`: 9.0.11 → **9.1.7**
- `lint-staged`: 15.2.2 → **16.4.0**

TypeScript 6.0.3 exposed four genuine type issues (see §8). All were fixed inline rather than deferred, as they were either straightforward casts or correct type-safety improvements. The `prettier-plugin-astro@0.14.1` regression on function declarations in partytown scripts was handled by excluding `Layout.astro` from formatting rather than modifying the file's semantics — this minimizes risk.

The risk register entry for "TS strictness flag on existing issue" (design §6) was triggered: TS 6.0.3 uncovered four type errors. Three were minor (cast/filter patterns); one required a JSDoc type cast in `eslint.config.js` due to a stale type definition in `@typescript-eslint/eslint-plugin` (types say `ClassicConfig.Config` but runtime returns `FlatConfig.ConfigArray`).

## 7. Risks introduced or accepted

- **`prettier-plugin-astro@0.14.1` parser regression**: The plugin cannot parse `function` declarations inside `<script type="text/partytown">` blocks, causing `SyntaxError: Unexpected token, expected "}"`. Workaround: `src/layouts/Layout.astro` excluded from formatting via `.prettierignore`. The file will be formatted once the upstream bug is fixed in a future `prettier-plugin-astro` release. This does not affect build correctness.
- **TypeScript 6.0.3 deprecation hints**: TS 6 surfaces deprecation warnings for `z` (astro:content's re-export of zod v3) and `React.FormEvent`. These are hints, not errors. The zod v3 → v4 migration is out of scope for this task and the broader upgrade plan. React 19's `FormEvent` deprecation will be addressed when relevant.
- **`@typescript-eslint/eslint-plugin` type mismatch**: The package's `index.d.ts` types `configs` as `Record<string, ClassicConfig.Config>` but `flat/recommended` at runtime returns a `FlatConfig.ConfigArray`. Fixed with a JSDoc cast. This is an upstream type definition defect.

## 8. Out-of-scope changes

- Fixed 4 TS 6 type errors that were only visible under the new TypeScript version:
  1. `eslint.config.js`: JSDoc cast for `tsPlugin.configs['flat/recommended']` spread (upstream type definition wrong).
  2. `src/pages/og.png.ts`: `new Uint8Array(buffer)` wrapper (TS 6 stricter Buffer → BodyInit assignability).
  3. `src/pages/posts/[slug]/index.png.ts`: same as above.
  4. `src/pages/posts/[slug]/index.astro`: type predicate filter on `getEntry` results (TS 6 correctly detects `undefined` possibility).

These were unavoidable — without the fixes, `pnpm astro check` (which is part of `pnpm build`) would fail.
