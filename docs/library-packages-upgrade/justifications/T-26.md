## 3. Why this approach

This task implements design §4 Task T-26 ("Bump content/build deps") and the plan's §4 step list. The plan mandates `pnpm add @latest` per group with a `pnpm build` validation gate between groups — this is precisely what was executed. No alternatives were considered for already-at-latest packages; running `pnpm add` for those would have been a no-op touching only the lockfile resolution timestamp. Risk register entry R7 (sharp pin removal) was already resolved by T-20; sharp remains at `^0.34.5` (current latest 0.34.5) and was not touched. The satori 0.10→0.26 jump (13 minor versions) was the highest-risk bump but validated successfully — the `satori` and `SatoriOptions` imports and the `satori(template, options)` call pattern in `generateOgImages.tsx` remained API-compatible.
