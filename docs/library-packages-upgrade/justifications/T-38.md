## 1. Goal recap

Bump Astro from 6.1.10 to 6.2.1 to resolve a known dev-toolbar race condition that produced recurring `504 Outdated Optimize Dep` errors on every cold-start cycle in development mode.

## 2. What changed

- `package.json` — `astro` bumped from `6.1.10` to `6.2.1` in dependencies.
- `pnpm-lock.yaml` — lockfile updated to reflect the new Astro version and any transitive dependency changes.
- `docs/library-packages-upgrade/backlog.yaml` — T-38 status updated from `backlog` → `in-progress` → `qa-pending`.

## 3. Why this approach

This task implements the Astro minor-version bump described in the upgrade backlog (T-38). The 6.1.x line had a known race between Vite's dependency optimizer re-bundling and Astro's dev toolbar dynamic imports, causing `504 Outdated Optimize Dep` responses on every cold-start for the toolbar chunk families (`ui-library-`, `audit-`, `xray-`, `toolbar-`, `settings-`, `dev-toolbar/entrypoint.js`). Astro's own dev-server update notice flagged 6.2.1 as available. The bump-first approach was taken as specified; no fallback (`devToolbar: { enabled: false }`) was needed because the bump alone eliminated all 504 errors. No peer packages required bumping: all `@astrojs/*` packages, `astro-expressive-code`, and `@expressive-code/*` remain compatible with Astro 6.2.1 at their current versions. The only peer warning from `tsconfck` (wanting `typescript@^5.0.0`) is benign since TypeScript 6.0.3 (already installed, a newer major) fully satisfies the requirement in practice. A React peer warning from `quicklink` inside `@divriots/jampack` is pre-existing and unrelated to this task.
