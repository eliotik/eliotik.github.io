## 1. Goal recap

Add `.github/workflows/ci.yml` so every pull request to `main` runs install / `astro check` / lint / build / `pnpm audit --prod`, establishing the CI gate that all later upgrade tasks depend on.

## 2. What changed

- `.github/workflows/ci.yml` — new file (40 lines). Triggers on `pull_request` to `main` and `workflow_dispatch`. Single `validate` job on `ubuntu-latest` that checks out the repo, installs Node from `.nvmrc`, enables Corepack and activates `pnpm@latest`, then runs `pnpm install --frozen-lockfile`, `pnpm astro check`, `pnpm lint`, `pnpm build`, and `pnpm audit --prod` (the audit step has `continue-on-error: true` because Dependabot owns blocking on vulnerabilities).
- `docs/library-packages-upgrade/backlog.yaml` — T-01 entry transitioned `backlog → in-progress` (work commit) and then `in-progress → qa-pending` (hand-off commit) per the dev-agent procedure. No other task entries touched.

## 3. Why this approach

This implements design §2 finding #1 ("No PR validation workflow") and finding #4 ("No `npm audit` / `pnpm audit` step in CI"), both of which the design assigns to T-01. The plan's task spec at §4 #task-t-01 dictates the exact YAML content, which is reproduced verbatim in `.github/workflows/ci.yml` — no "improvements," no extra steps, no quoting normalization. Risk register entry R6 (pnpm migration breaks `withastro/action` auto-detection) is partially mitigated here by explicitly enabling Corepack and activating `pnpm@latest` rather than relying on detection; T-03 will set the same pattern in `deploy.yml`. An alternative — folding install/check/lint/build into separate jobs — was considered and rejected because the plan specifies a single `validate` job and parallel jobs would obscure failure ordering for this small build.

The workflow intentionally references `pnpm`, which does not yet exist in the repository — T-03 introduces it. Per the plan note (§4 #task-t-01 step 4), this is expected: T-02 and T-03 will land via `workflow_dispatch` / admin merge before pnpm exists, after which the gate becomes effective for every subsequent PR.
