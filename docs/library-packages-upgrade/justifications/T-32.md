## 1. Goal recap

Added explicit "Model selection" sections to `dev-agent.md` and `qa-agent.md` so all future campaign dispatches have unambiguous, codified model directives.

## 2. What changed

- `docs/library-packages-upgrade/agent-prompts/dev-agent.md` — added "## Model selection" section stating Dev Agents MUST run on Sonnet (e.g. `claude-sonnet-4-6`), placed after the opening description paragraph and before "## Inputs you receive".
- `docs/library-packages-upgrade/agent-prompts/qa-agent.md` — added "## Model selection" section stating QA Agents MUST run on Opus (e.g. `claude-opus-4-7`), placed after the opening description paragraph and before "## Inputs you receive".
- `docs/library-packages-upgrade/backlog.yaml` — T-32 status updated from `backlog` → `in-progress` → `qa-pending`.

## 3. Why this approach

This task is specified in the upgrade plan as a docs-only chore (T-32, phase 3, lane: docs). The model-selection rule was established mid-campaign by the orchestrator but was not yet written into the procedure files, creating a risk that future dispatches would be launched on the wrong model (either wasting Opus budget on routine implementation work or producing lower-quality QA reviews from Sonnet). Placing the directive at the top of each procedure file — just after the preamble and before the procedural steps — ensures it is the first substantive section a dispatched agent reads, minimizing the chance of it being overlooked. No alternatives were considered for placement, as the spec explicitly suggested "after the header, before Inputs you receive." The risk this mitigates (R-model-budget in the design's risk register, if one were added) is operational: inconsistent model assignment across a multi-agent campaign leads to either degraded review quality or unnecessary cost overruns.
