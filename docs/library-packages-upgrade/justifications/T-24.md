## 1. Goal recap

Removed the unused `flowbite` and `flowbite-react` npm packages from `dependencies`, and removed the dangling `flowbite-react` reference from `vite.optimizeDeps.include` in `astro.config.mjs`.

## 2. What changed

- `package.json` — `flowbite 2.3.0` and `flowbite-react 0.7.2` removed from `dependencies`.
- `pnpm-lock.yaml` — updated automatically by `pnpm remove flowbite flowbite-react`.
- `astro.config.mjs` — removed `"flowbite-react"` from `vite.optimizeDeps.include`; array is now `["fuse.js", "react", "react-dom"]`.
- `docs/library-packages-upgrade/backlog.yaml` — T-24 status updated to `in-progress` (then `qa-pending` on hand-off).
- `docs/library-packages-upgrade/justifications/T-24.md` — this file (created).

## 3. Why this approach

This task implements design §4 Phase 2 task T-24: "Remove flowbite." All flowbite imports were already stripped in T-10 (Carousel replaced with CSS scroll-snap) and T-11 (ThemeModeScript replaced with inline pre-paint script). The only remaining references were the package.json dependency entries and the `optimizeDeps.include` reference in `astro.config.mjs`. Design §6 risk register entry R5 ("flowbite-react removal leaves a dangling optimizeDeps.include reference that breaks Vite warm-up") is directly addressed by updating `astro.config.mjs`. The `pnpm.peerDependencyRules` block described in the plan's step 7 was not present in `package.json` (T-03's QA report confirms it was never added), so no cleanup was needed there.
