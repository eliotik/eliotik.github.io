## 1. Goal recap

Bumped React 18 → 19, react-dom 18 → 19, @types/react 18 → 19, @types/react-dom (new, ^19), keeping @astrojs/react at 5.0.4 which already supports React 19, and audited all 8 `.tsx` components for React 19 breaking changes.

## 2. What changed

- `package.json`: `react` 18.2.0 → 19.2.5, `react-dom` 18.2.0 → 19.2.5 (both in devDependencies, as placed by T-20)
- `package.json`: `@types/react` 18.2.61 → ^19.2.14
- `package.json`: `@types/react-dom` added at ^19.2.3 (was missing entirely)
- `pnpm-lock.yaml`: updated to reflect new resolved versions
- `@astrojs/react`: remains at 5.0.4 — confirmed to already support React 19 via peer deps `react: '^17.0.2 || ^18.0.0 || ^19.0.0'`
- `astro.config.mjs`: no change — `experimentalReactChildren: true` is still a valid and supported option in @astrojs/react@5.0.4
- `tsconfig.json`: no change — `"jsx": "react-jsx"` is already the correct React 19 JSX runtime setting
- All 8 `.tsx` components: no code changes required (see §3 and the component audit table below)

## 3. Why this approach

This implements design §4 T-21 and addresses risk register entry R3 (React 19 silent runtime breaks from ref/defaultProps changes). The upgrade targets `react@^19` (landing on 19.2.5, the latest stable) and `@types/react@^19` (19.2.14). `@astrojs/react` was already bumped to 5.0.4 by T-20 and its peer dependency range already includes `react@^19.0.0` — a further bump is unnecessary and outside scope. The `experimentalReactChildren` flag was verified to remain present in @astrojs/react@5.0.4 (it was not stabilized into a non-experimental name), so `astro.config.mjs` requires no change. All 8 components use default parameter syntax for optional props, use no `forwardRef`, `defaultProps`, `propTypes`, `Children.map`, or `cloneElement`, and are thus already React 19-compatible with zero code changes required.

## 7. Risks introduced or accepted

- `flowbite-react@0.7.2` emits peer dependency warnings under React 19 (`react@^18` expected, found `19.2.5`). This is expected and known — T-24 removes flowbite-react entirely. Not a runtime issue because flowbite-react is not used in any rendered component (T-10 and T-11 already removed all imports).
- `react-indiana-drag-scroll` (a transitive dep of flowbite-react) similarly warns for React 19. Same root cause and same mitigation (T-24).
- `@astrojs/tailwind 6.0.2` warns about unmet peer `astro@^3.0.0 || ^4.0.0 || ^5.0.0` (found 6.1.10). This is a pre-existing warning from T-20, not introduced here.
