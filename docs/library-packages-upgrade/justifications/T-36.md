## 1. Goal recap

Added left/right navigation arrow buttons to the CSS scroll-snap carousel in `ImageSliderClient.tsx`, replacing the scrollbar UX with button-driven navigation while hiding the horizontal scrollbar.

## 2. What changed

- `src/components/ImageSliderClient.tsx` — Rewrote the component to add React state (`canScrollPrev`/`canScrollNext`), a `useRef` for the scrollable div, scroll/resize event listeners, and two absolute-positioned prev/next buttons with inline SVG chevron icons. Added Tailwind escape-hatch classes to hide the scrollbar across all browsers.

## 3. Why this approach

This task addresses Observation #5 from manual verification (2026-04-30), which reported the scrollbar UX was suboptimal. The implementation uses only React state and vanilla scroll APIs — no new external packages — satisfying the "no new packages" constraint explicitly stated in the task. The CSS scroll-snap behavior is preserved intact, and all existing accessibility semantics (`role="region"`, `aria-roledescription`, `tabIndex={0}`, `aria-label`) are maintained.

Alternative considered: using CSS `scroll-snap` with keyboard-only navigation and no buttons — rejected because the user explicitly requested visible left/right arrow buttons similar to the original flowbite carousel. Using an icon library (heroicons, lucide) was also considered and rejected per the no-new-packages constraint; inline SVG chevrons were used instead.

The scrollbar hiding approach uses Tailwind's arbitrary property escape hatch (`[scrollbar-width:none]`, `[-ms-overflow-style:none]`, `[&::-webkit-scrollbar]:hidden`) covering Firefox, IE/Edge legacy, and Webkit/Blink browsers respectively.

## 7. Risks introduced or accepted

- The smooth-scroll animation (`behavior: 'smooth'`) does not function in headless browser environments (Chrome MCP during testing). Functional verification was done by programmatically setting `scrollLeft` to confirm state changes. In a real browser, smooth scrolling works as expected per the browser's scroll implementation.
- The `updateScrollState` function fires on every `scroll` event; for carousels with many images this could cause frequent re-renders. However, React batches state updates, and real-world carousels on this blog have 2-5 images — no performance concern.
