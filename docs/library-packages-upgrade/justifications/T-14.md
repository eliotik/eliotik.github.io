## 1. Goal recap

Add ESLint to lint-staged so that all staged JS/TS/Astro files are linted (with auto-fix) on every commit, complementing the existing Prettier formatting step.

## 2. What changed

- `package.json` (`lint-staged` block): added `"*.{js,jsx,ts,tsx,astro}": ["eslint --fix"]` alongside the existing prettier entry.
- `.husky/pre-commit`: confirmed as already the v9 minimal one-liner `pnpm exec lint-staged` (no change required — T-03 handled this).
- `.husky/_/`: the legacy shim directory is not present in git (not tracked); only exists as a local artifact in the main worktree from an older Husky installation. Nothing to delete in this branch.

## 3. Why this approach

This task implements design §2 findings #6 ("Pre-commit only runs Prettier; ESLint never runs locally before push") and #7 ("Husky still uses the deprecated `_/husky.sh` shim") from `2026-04-29-upgrade-design.md`.

The `_/husky.sh` shim issue (#7) was already resolved by T-03, which switched the pre-commit hook to `pnpm exec lint-staged` — the v9 minimal format. T-14 confirms this and focuses on finding #6: adding ESLint to lint-staged.

The `eslint --fix` pattern was added alongside the existing prettier step as a separate lint-staged key targeting `*.{js,jsx,ts,tsx,astro}`. This matches the pattern specified in plan §4 #task-t-14 step 5 exactly. No alternative pattern was considered — the plan is explicit.

No risk register entries from design §6 are introduced by this change. Adding `eslint --fix` to pre-commit only affects local developer workflow, not the build or deployed output.
