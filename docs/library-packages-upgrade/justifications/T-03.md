## 7. Risks introduced or accepted

- **Newly added: `pnpm.onlyBuiltDependencies` block in `package.json`** — pnpm 10 (released early 2025) introduced an opt-in gate on dependency post-install scripts as a supply-chain hardening measure. By default, post-install scripts of transitive deps are blocked, and `pnpm install` emits "Ignored build scripts" warnings. The blocked packages here all need their post-install to function:
  - `sharp` (0.32.6) — downloads/copies a prebuilt libvips binary into `build/Release/sharp-darwin-arm64v8.node`. Without it, image optimization (Astro `<Image>`, `satori`, `jampack`) fails at first call. Verified after install: `node_modules/sharp/build/Release/sharp-darwin-arm64v8.node` is present.
  - `esbuild` — postinstall downloads the platform-specific binary used by Vite and Astro for build/dev bundling. Verified: `node_modules/esbuild/bin/esbuild` is present.
  - `@swc/core` — same pattern (native binary). Used transitively by `flowbite-react > next-contentlayer > next > @swc/core`.
  - `protobufjs` — postinstall pre-generates protobuf descriptors. Used transitively under `contentlayer`'s telemetry path. Verified: `node_modules/protobufjs/dist/` is populated.
  - `contentlayer` — its own `postinstall` runs `node ./bin/cli.cjs postinstall` which is benign at install time but is the pattern contentlayer uses to register its CLI. Used transitively under `flowbite-react`.
  After T-24 removes `flowbite-react`, `@swc/core`, `contentlayer`, and `protobufjs` will fall out of the tree and can be pruned from this list. After T-26 unpins `sharp` to its current version, the entry stays. T-26 also re-evaluates whether `sharp` is still needed at all under Astro 5's image service.

  **One-place-only rule respected:** initially `pnpm approve-builds --all` auto-generated a `pnpm-workspace.yaml` with the (non-standard for a single-package repo) `allowBuilds:` map. This was deleted in favor of `package.json` `pnpm.onlyBuiltDependencies` (the canonical pnpm-10 syntax for non-workspace projects), so config lives in exactly one file. Verified: clean reinstall from scratch with `rm -rf node_modules && pnpm install --frozen-lockfile` produces no "Ignored build scripts" warning, and all five native packages have their build artifacts.

- **Peer-dependency warnings during `pnpm import` (informational, not blocking):**
  - `contentlayer 0.3.4 > @contentlayer/client > @contentlayer/core` — wants `esbuild@0.17.x || 0.18.x`, found `0.19.12`. Transitive only; contentlayer is consumed via `flowbite-react`, removed in T-24.
  - `@divriots/jampack > quicklink 2.3.0` — wants `react@^16.8.0` and `react-dom@^16.8.0`, found `18.2.0`. quicklink's React peer is for an opt-in React component the project does not import; jampack's CLI usage is unaffected. React 19 lands in T-21.

  **No `pnpm.peerDependencyRules` block was added** — the plan §4 #task-t-03 step 7 prescribed it only IF `pnpm install` errored. It did not. T-24 step 7's note about "remove the peerDependencyRules block added during T-03" therefore becomes a no-op.

- **Husky `install command is deprecated` warning** — surfaced on every install via `prepare: husky install`. Husky 9 deprecates the `install` subcommand in favor of the bare `husky` CLI; v10 will remove it. T-14 modernizes the script. Accepted noise until then.

## 8. Out-of-scope changes

- The `fresh` script in `package.json` referenced `yarn dev` literally. Plan §4 #task-t-03 step 10 only enumerates the `CLAUDE.md` rename, but leaving a literal `yarn dev` inside a script the new `pnpm` toolchain executes would break `pnpm fresh` for any contributor. Rename was unavoidable; it's scoped to a single shell-string substitution.
- Adding `pnpm.onlyBuiltDependencies` to `package.json` is not in the plan's step list either, but **without it pnpm 10's default behavior leaves `sharp` unbuilt**, which would break `pnpm build` (covered in §5.4 above) on a fresh checkout (i.e. for the CI runner and for anyone cloning this branch). Documented in §7. The plan was authored against pnpm <10's default-allow behavior; this gate is a 2025 change pnpm shipped after the design doc was written.
