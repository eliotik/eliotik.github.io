## 3. Why this approach

This task implements design §4 Phase 1 task T-12 and mitigates risk register entry R8 (ESLint 9 + astro-eslint-parser drift). The flat config is authored now so T-23 has a working foundation when it bumps ESLint to v9 and deletes `.eslintrc.cjs`.

The plan template was followed closely, with one deviation: the plan expected `pnpm lint` to stay on the legacy config. In practice, ESLint 8.57.0 auto-detects `eslint.config.js` by default (see `flat-eslint.js:1133` — `shouldUseFlatConfig()` returns true when `eslint.config.js` is present and no env var is set). This means `pnpm lint` immediately uses the flat config. The config was therefore ported to full fidelity to maintain the same 11-error baseline, rather than deferring rule accuracy to T-23.

An alternative considered: renaming the file (e.g. `eslint.config.flat.js`) to avoid auto-detection. Rejected because the plan specifies `eslint.config.js` as the filename and T-23 depends on that exact name.

## 7. Risks introduced or accepted

**ESLint 8.57 auto-detection behavior (plan assumption violation):**
ESLint 8.57.0's `shouldUseFlatConfig()` function auto-detects `eslint.config.js` when present, without requiring `ESLINT_USE_FLAT_CONFIG=true`. The plan assumed legacy would remain active until T-23, but the flat config is already the active config as of this commit. This is acceptable because:
1. The flat config is a faithful port — same 11 errors as legacy (verified above)
2. The legacy `.eslintrc.cjs` still loads correctly under `ESLINT_USE_FLAT_CONFIG=false`
3. T-23 still has work to do: bump ESLint to 9, bump plugin versions to flat-config-native releases, run `--fix`, delete `.eslintrc.cjs`

**Rules ported (all from `.eslintrc.cjs`):**

| Source | Flat config block | Status |
|--------|------------------|--------|
| `eslint:recommended` | Block 1a (js.configs.recommended.rules for JS/TS files), Block 3b (same rules for .astro files) | Fully ported |
| `plugin:@typescript-eslint/recommended` | Block 1b (@typescript-eslint/* rules for all JS/TS) + Block 1c (TS-scoped core overrides for *.ts/tsx/mts/cts only) | Fully ported; scoping preserved |
| `plugin:astro/recommended` | Block 3b (astroPlugin.configs.recommended.rules) | Fully ported (7 rules) |
| `plugin:astro/jsx-a11y-recommended` | Block 3b (astroPlugin.configs['jsx-a11y-recommended'].rules) | Fully ported (34 rules) |
| `.eslintrc.{js,cjs}` override (node/script) | Block 2 | Fully ported |
| `*.astro` override (astro parser) | Block 3b | Fully ported |
| `rules: {}` (empty in legacy) | All blocks inherit recommended rules | No additional rules to port |

**Rules deferred to T-23:**
- None — all rules from `.eslintrc.cjs` are ported. T-23 will additionally upgrade plugin versions to their flat-config-native v8+ releases, which may change rule sets, and will run `--fix` on the 11 pre-existing errors.

**Non-standard globals:**
The flat config declares an explicit `sharedGlobals` object for browser/node/es2022 globals (replacing legacy `env: {node, browser, es2022}`). The `dataLayer` Google Tag Manager global is intentionally excluded to preserve the `no-undef` error in `Layout.astro:132` that exists in the legacy config.

**Processor registration:**
The `astro-eslint-parser` processor must be explicitly registered in flat config (`processor: astroPlugin.processors['.astro']`). In legacy config it was auto-registered via the plugin's `overrides` block. Without this, inline `<script>` blocks in `.astro` files are not linted.
