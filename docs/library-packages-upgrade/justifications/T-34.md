## 1. Goal recap

Restore three visual regressions introduced by the Tailwind 3 → 4 migration: buttons missing `cursor:pointer`, search input missing a visible border, and inline `<code>` elements rendering dark-on-dark in dark mode.

## 2. What changed

- `src/styles/base.css` — Added `@layer base` rule giving `button:not(:disabled)` and `[role='button']:not(:disabled)` `cursor: pointer`, matching Tailwind 3 preflight behaviour.
- `src/styles/base.css` — Added unlayered rule `html[data-theme='dark'] .prose { --tw-prose-code: var(--color-skin-base); }` to fix dark-mode inline code colour.
- `src/components/Search.tsx` — Changed search `<input>` border class from `border-skin-fill/40` (invisible near-white in light mode) to `border-skin-line` (the explicit border/line token).

## 3. Why this approach

This task implements design §1 criterion 5 (routes render correctly) by fixing three visual regressions identified in post-T-30 manual verification. The cursor fix follows the canonical Tailwind 4 migration guide (https://tailwindcss.com/docs/upgrade-guide#default-button-cursor); it uses `@layer base` so it doesn't conflict with component-level overrides. The border fix targets the specific element rather than a global `*` selector — empirical investigation (DevTools inspection) showed `border-skin-fill` in light mode resolves to near-white at 40% opacity (invisible), while `border-skin-line` resolves to the project's designated border token `rgb(236, 233, 233)` in light and `rgb(171, 75, 8)` in dark, both readable. The dark-code fix uses an unlayered CSS rule (outside all `@layer` blocks) to override the `--tw-prose-code` CSS variable on `.prose`: this is necessary because `@tailwindcss/typography` places its code colour rule in `@layer utilities`, which has higher cascade priority than `@layer base` regardless of selector specificity — our previous `color: inherit` in `@layer base` was being silently overridden. The unlayered override beats all layered rules per CSS cascade specification.

## 7. Risks introduced or accepted

- The unlayered `html[data-theme='dark'] .prose { --tw-prose-code: ... }` rule is intentionally placed outside `@layer` blocks. Future additions of Tailwind utilities that also target `--tw-prose-code` in unlayered CSS would need to be placed after this rule if they should win. Low probability given the project's CSS structure.
- The `border-skin-line` token in dark mode resolves to `rgb(171, 75, 8)` (orange/rust). This matches the project's dark-mode border palette and is consistent with other bordered elements (tables, images). It differs from production's `rgba(40, 39, 40, 0.4)` (semi-transparent text-base), but is more semantically correct (using the dedicated border token) and visually appropriate.
