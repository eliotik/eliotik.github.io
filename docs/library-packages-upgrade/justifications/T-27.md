## 1. Goal recap

Bump all pinned GitHub Actions versions in `.github/workflows/ci.yml` and `.github/workflows/deploy.yml` to the current latest stable major release.

## 2. What changed

- `.github/workflows/ci.yml`: `actions/checkout@v4` → `@v6`; `actions/setup-node@v4` → `@v6`
- `.github/workflows/deploy.yml`: `actions/checkout@v4` → `@v6`; `withastro/action@v4` → `@v6`; `actions/deploy-pages@v4` → `@v5`

## 3. Why this approach

This task implements design §2 CI/CD audit finding #5 ("withastro/action@v4 not yet validated against Astro 5 + Node 22"). Versions were determined by querying GitHub releases API (`gh api repos/<owner>/<repo>/releases/latest`) for each action. Only the major version tag (`@vN`) is used per the plan's explicit constraint ("Do NOT pin to a SHA"). Release notes for each new major were checked for breaking input changes; none affect the current workflow configurations (all inputs used — `node-version-file`, `node-version`, `package-manager` — remain supported). The single alternative (staying on `@v4`) was rejected because each action's `@v4` runner now runs on Node 20, while GitHub is migrating action runners to Node 24 for performance and security; using the latest major reduces forward-compatibility risk.

## 7. Risks introduced or accepted

- `actions/setup-node@v6` auto-caches npm dependencies by default when `packageManager` field is present in `package.json`. Since the project uses pnpm (not npm), this automatic caching does not activate. The design's intent is unaffected.
- `actions/checkout@v5` and `@v6` require runner version ≥ v2.327.1. GitHub-hosted `ubuntu-latest` runners are always at current, so no risk for GitHub.com (design §2 finding #8 notes no staging env, but GitHub.com runners are guaranteed current).
- `withastro/action@v6` updates internal dependencies (Node, pnpm, bun, cache actions) — no breaking input changes to `node-version` or `package-manager`. Verified by inspecting `action.yml` at HEAD.
