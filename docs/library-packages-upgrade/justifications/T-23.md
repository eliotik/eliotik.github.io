## 3. Why this approach

This task implements design §4 Phase 2 task T-23 and resolves risk register entry R8 (ESLint 9 + `astro-eslint-parser` drift). The flat config was rewritten to use native presets (`flat/recommended`) rather than continuing T-12's manual rule expansion. The v8 typescript-eslint plugin and v1 eslint-plugin-astro both ship `flat/*` config exports that handle parser, processor, and rule wiring — this approach is cleaner and future-proof.

Alternatives considered:
- **Keep T-12's hand-expansion** — rejected because it carries renamed/removed rules (`@typescript-eslint/ban-types`, `@typescript-eslint/no-var-requires`, `@typescript-eslint/no-loss-of-precision`) that no longer exist in v8, which would cause config-load errors.
- **Use `typescript-eslint` wrapper package** — not installed; `@typescript-eslint/eslint-plugin`'s `flat/recommended` export achieves the same result without an extra dependency.

**`src/env.d.ts` disposition:** Added to `ignores` in `eslint.config.js`. This file is auto-generated by Astro on every `astro sync` and uses a mandatory triple-slash reference that `@typescript-eslint/triple-slash-reference` would flag. Ignoring is the correct approach for auto-generated files that cannot be modified.

**`.eslintignore` deletion:** ESLint 9 emits a deprecation warning for `.eslintignore`. All paths from the file have been migrated to the `ignores` array in `eslint.config.js` (`dist/`, `.astro/`, `node_modules/`, `.husky/`, `.vscode/`, `public/`, and `src/env.d.ts`).

**`public/toggle-theme.js`:** Was excluded by the old `.eslintignore`. Continues to be excluded via `public/` in `ignores`. The file uses browser globals (`window`, `document`, `localStorage`) without importing them — linting it would require a separate config block with browser globals, which is out of scope for this task.

**GTM `arguments` disable comment:** The `prefer-rest-params` disable comment on `Layout.astro:131` is a boundary case — this is the standard Google Analytics / GTM `gtag` function that relies on `arguments` by design. Converting to rest params would break the GA integration.

**Breadcrumbs.astro `&&` → `if` rewrites:** These were short-circuit patterns used as control flow (`condition && sideEffect()`). The rewrite to proper `if` statements is semantically equivalent and is the idiomatic fix per `@typescript-eslint/no-unused-expressions`.

## 8. Out-of-scope changes

The `.eslintignore` deletion is technically beyond the literal T-23 task description (which says delete `.eslintrc.cjs`), but is required because ESLint 9 no longer reads `.eslintignore` and emits a deprecation warning. Leaving it would produce a warning on every lint run. The migration of its contents to `eslint.config.js` `ignores` is the correct ESLint 9 upgrade procedure.
