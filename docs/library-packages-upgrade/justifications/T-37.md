## 1. Goal recap

Fix three distinct user-reported regressions: (A) wide Markdown tables in `/posts/ems-connecting-the-systems/` force horizontal page overflow on mobile viewports (~390px), making the page appear to have "40% right padding"; (B) `astro:before-swap` listener cleanup is missing, causing scroll and back-to-top handlers to stack up across ClientRouter navigations, contributing to `InvalidStateError: Transition was aborted` console noise; (C) a redundant `<link rel="preload" as="style">` for the Google Fonts stylesheet triggers a "preloaded but not used within a few seconds" browser warning on every ClientRouter navigation.

## 2. What changed

- `src/styles/base.css`: Added `@media (max-width: 768px)` rule making `.prose :where(table)` a scrollable block so wide tables scroll horizontally inside their own container rather than forcing the page wider than the mobile viewport.
- `src/layouts/PostDetails.astro`: Refactored the inline `<script is:inline>` to extract `backToTopHandler` as a named function reference so it can be removed via `removeEventListener`; added `detachScrollListener()` and `detachBackToTop()` functions; registered an `astro:before-swap` listener (with `{ once: true }`) inside `initPostDetails()` to clean up both listeners before the next View Transition DOM swap.
- `src/layouts/Layout.astro`: Removed the `<link rel="preload" as="style" ...>` tag for the IBM Plex Mono Google Font. The `media="print" onload="this.media='all'"` non-blocking stylesheet load is already sufficient; the preload was redundant and caused browser warnings on ClientRouter SPA navigations.

## 3. Why this approach

This task addresses design §1 success criterion 5 (local dev server renders correctly on the key routes) and §6 risk register R1 (Tailwind 4 prose rendering regressions). The mobile table overflow is a CSS containment problem: the Markdown table renders at its natural content width (~1200px on desktop) and, without any overflow constraint, forces its ancestor chain and the page-level scroll container to that same width. The fix — `display: block; overflow-x: auto` scoped to mobile via `@media (max-width: 768px)` — is the standard pattern for prose-embedded wide tables and is narrowly scoped so desktop behavior (full prose flow) is unchanged. An alternative was considered (adding `min-w-0` to the article flex/grid child per Approach 2 in the brief), but investigation of the DOM hierarchy (`body: flex-col` → `main: block` → `article: block`) confirmed there is no flex-row or grid track causing a min-content-expansion; the table is the direct cause, so Approach 1 (table overflow CSS) is both necessary and sufficient. The listener cleanup fix prevents handlers from stacking on every ClientRouter navigation; using `{ once: true }` on the `astro:before-swap` cleanup handler is idempotent by design — it fires exactly once per navigation cycle, then removes itself. Removing the preload link is Fix A (simplest) from Observation C — the `media="print" onload` swap already makes the stylesheet non-blocking; the preload added no value and was triggering browser warnings because ClientRouter re-emits head tags on navigation while the stylesheet is already cached.

## 7. Risks introduced or accepted

- The table `display: block` at mobile removes some default table layout behavior (e.g. the table no longer participates in flex/block flow as an inline-table). This is only active at ≤768px and the trade-off (scrollable vs broken layout) clearly favors scrollability. Desktop typography is unaffected.
- The `astro:before-swap` listener with `{ once: true }` fires and removes itself before each DOM swap. If a page with `#back-to-top` (PostDetails) navigates to another PostDetails page, the `astro:after-swap` re-registers `initPostDetails()` which re-registers the cleanup listener — the cycle is correct.
- The `InvalidStateError: Transition was aborted` console error (rapid-click race in View Transitions API) is mitigated by fixing the listener leak (fewer stacked handlers reduces state collision risk) but is not fully eliminated — it is an upstream Astro/browser View Transitions API behavior when the user clicks a link before the previous transition completes. This is documented as a known limitation.
