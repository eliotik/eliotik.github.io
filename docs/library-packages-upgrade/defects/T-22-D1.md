## Summary

Tailwind 4's `outline-2` utility now emits `outline-style: solid` in addition to `outline-width: 2px`; in Tailwind 3 it only emitted the width. The base rule `a { @apply outline-2 outline-offset-1 outline-skin-accent ... }` therefore paints a permanent visible 2px solid outline around every `<a>` site-wide. The header navigation no longer fits horizontally and stacks vertically; every link, button, and tag pill on every page is wrapped in a coloured box. This is a visual regression versus the pre-T-22 baseline.

## Reproduction

1. `git checkout upgrade/T-22-tailwind-4`
2. `pnpm install --frozen-lockfile`
3. `pnpm dev` (note the chosen port)
4. Open `http://localhost:<port>/` in a 1280×1800 viewport.
5. Observe: every nav link (`Posts`, `Tip-tops`, `Threads`, `Tags`, `About`), the search/theme buttons, the `Motivation is a trap…` link, the `Recent Posts` link cards, and the `All Posts →` button each have a visible 2px solid outline around them. Header nav is forced into a vertical stack on the right.
6. Switch to `main` (commit `4481981`) and repeat: outlines are not visible — the same `<a>` elements compute `outline-style: none`.

The dev's own captures show the same regression but were marked PASS in justification §6 because they were not diffed against the baseline. Examples in the dev's set: `qa-runs/T-22-20260429/visual/01-home-dark.png`, `02-posts-list.png`, `04-tips-list.png`, `06-tags.png` — all show outline boxes around interactive elements that the baseline does not have.

The same regression manifests on every other route too (posts list, post detail card, tips list, tag detail, threads list, about, 404) because the rule targets the bare `a` selector.

## Files implicated

- `src/styles/base.css:103-106` — the only site in `src/` that applies an `outline-N` utility outside `:focus-visible:`. Verified by `grep -rn 'outline-[0-9]' src/`. The original Tailwind 3 rule existed in the same form at the same line; it became visible only when Tailwind 4 changed `outline-2`'s emission.

  ```css
  a {
    @apply outline-2 outline-offset-1 outline-skin-accent
    focus-visible:no-underline focus-visible:outline-dashed;
  }
  ```

  No other source file uses an `outline-[0-9]` width utility unconditionally; the custom `@utility focus-outline` (lines 203–211) already gates the visible style behind `:focus-visible` and is unaffected.

## Suggested fix direction (optional)

The base `a` rule needs to either (a) gate the visible outline behind `focus-visible:` (which is what the original effective behavior was, since v3 left `outline-style: none` by default), or (b) explicitly reset `outline-style` to `none` on the base rule so v4's new emission doesn't paint a constant outline. The custom `focus-outline` utility on lines 203–211 is one viable shape — applying `@apply focus-outline` to `a` and removing the always-on `outline-2` would match the intent of the original config.

After the fix, re-run visual smoke against `baseline/01-home.png` and ensure each link's computed `outline-style` is `none` outside `:focus-visible`.
